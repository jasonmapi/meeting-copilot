# 质量检查与回归场景

## 发布前必查

- [ ] 同名企业、母子公司、曾用名已区分；主体不能确认时报告没有合并候选数据。
- [ ] 重要事实都有原文、证据ID、状态和时点；未打开原文的内容仍是线索。
- [ ] 来源等级与断言状态分别记录；转载按源头去重；重要单源断言披露单源。
- [ ] PDF页码、专利/证书编号、日期、单位、统计口径已对照原件；打不开已说明。
- [ ] 当前状态与历史记录分开；拟认定/认定、申请/授权、受让/原创、公开/登记没有混淆。
- [ ] 覆盖矩阵每一维有结果或缺口；“未检索到”没有写成不存在。
- [ ] 推断含证据链、替代解释和验证问题；个人信息只保留必要商务用途。
- [ ] AI机会含数据、人工审核、负责人、非AI方案及门槛；未知维度用区间。
- [ ] 评分公式方向与权重正确；区间重叠不过度排序；无虚构ROI和预算。
- [ ] 培训、试点、生产上线和产品控制应用边界清楚；验收独立于演示样本。
- [ ] 访谈优先解决最影响排序的未知项；路线图说明条件和失败退出。
- [ ] 对客版清楚、可引用；内部台账可追溯；未擅自发送或联系任何人。

主体混淆、无依据企业事实、虚构来源或承诺、越权使用资料属于阻断项：纠正后再交付。信息缺失本身不是阻断项，但必须披露并降低结论强度。

## 行为回归用例

用模拟输入检查判断，禁止为测试伪造真实访问记录。涉及联网的整流程测试需单独执行并注明日期。

| 输入情境 | 应有行为 | 失败表现 |
|---|---|---|
| 同名企业分别位于两地 | 分候选主体、寻求区分标识 | 合并业务与专利 |
| 两网站转载同一篇宣传稿 | 一个来源家族，企业自述 | 宣称两家独立来源已证实 |
| 官方附件是“拟认定名单” | 精确写拟认定，继续找最终记录 | 写成已取得资质 |
| 旧招聘人数冲突 | 并列日期口径，转访谈 | 取平均当当前人数 |
| 专利出现AI字样 | 只说明公开技术线索 | 推出量产、成熟AI团队或需求预算 |
| 无法联网，仅有历史报告 | 输出待核验台账和检索计划 | 伪造当天已核实事实 |
| 数据和负责人未知，其余均4分 | D/O=1—5，总分为59—87；门槛待确认 | 默认中分并承诺优先上线 |
| 没找到行政处罚 | 写明查询渠道和未检索到 | 声称公司绝无处罚 |
| 释放工时可观但复核耗时更长 | 重测净耗时，暂缓/停止 | 仅统计模型生成速度 |
| 用户只要某企业AI拜访速览 | 保留关键核验与缺口、缩减深度 | 强行执行庞大专项审计 |

## 迭代记录方法

先用真实任务观察遗漏、错误、耗时及客户反馈，再修改最小必要规则。建议指标：重要断言可追溯率、访谈后假设保留率、优先机会变更原因、试点评测通过率。不能通过重复增加规则来掩盖信息缺口。变更评分权重时保留版本，避免将两版分数直接比较。
