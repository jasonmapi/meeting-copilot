# 企业AI售前研究报告严格复用规范

版本：2.0.0｜公开版结构规范｜企业事实须每次独立核实。

本规范固定报告结构与展示契约；企业事实、来源、机会和访谈回答必须重新研究。交付为完整11章HTML、同内容Markdown、结构化报告数据、证据台账、检索日志与一致性检查。网页为主要阅读版，Markdown为可编辑底稿。报告不是工商、知识产权或投资法律意见。

## 1. 使用边界

本包的assets/structure.json、deliverable-template.md、report-ui.css与report-ui.js共同定义报告结构和交互。使用V×E评分、区间、筛选、排序、访谈勾选和打印展示；评分只是讨论假设。不得照搬前一家企业的事实、来源或结论。

若迁移用户已有报告且只调整界面，保留其原评分与题数，明确版本差异。不能将功能重建称为原始报告像素级复刻。

## 2. 固定11章与模块契约

一级标题仅公司全称；副标题固定“企业公开信息尽调 · AI培训与落地项目售前研究”；元信息显示研究日期、Asia/Singapore、用途“客户拜访与需求挖掘”、模板版本、状态图例。不能拿新访问日期替代资料发生日。

| 顺序/固定标题 | 固定内容与字段 | 固定展示及不允许省略项 |
|---|---|---|
| 一、先给你最重要的判断 | 核心判断；5条关键发现（每条状态/依据/含义）；建议定位；判断范围 | 开篇加粗结论＋编号5条；结论需就近引用；无事实时保留未知发现 |
| 二、企业基本档案 | 企业名称、经营状态、成立日期、注册资本、法定代表人、企业类型、统一社会信用代码、注册地址；工商来源、冲突、复核提示 | 八字段固定顺序；表格/信息卡；信用代码可选中复制；不得将注册资本等同收入；规模补充置于本章末 |
| 三、主营业务、产品与组织结构 | 3.1 公开资料确认的业务方向；3.2 历史招聘透露的部门和业务流程 | 3.1表头严格为“业务领域/已发现的信息/对AI售前的价值”；3.2岗位卡含岗位名、历史任务、日期/来源、薪酬或未知、AI切入及组织假设；保留市场、客户、产能缺口 |

| 五、销售联系方式与拜访信息 | 注册/经营/候选拜访地址分别写；公共商务电话、邮箱、联系角色、官网状态、地图 | 地址卡＋可复制文本＋地图；未经核验的联系人不得称决策人；官网不从邮箱域名直接推定；地址冲突保留多个候选 |

第三章的岗位数量、第四章的专利数量、第六章的机会数量可随证据变化，模块与字段不得减少。没有专利则保留4.1并写未知、检索范围和补证；不能移植母版成果凑数。表格行数可变，仅第九章12类与第七章12题固定。主报告不增加第十二章，台账等作为伴随文件。

第九章固定类别：股权与管理团队；营业收入、利润；现有客户和主要订单；产品目录和规格；完整专利及软著清单；招投标与供应商关系；司法、行政及经营风险；官网和社交媒体；当前员工与岗位数量；信息化基础；AI使用现状与预算；数据保密及部署要求。

阶段固定为：企业AI认知与需求诊断 → 分岗位AI实战培训 → 选择1–2个小项目试点 → 企业持续应用与安全治理。

## 3. 来源检索与核验方法

每次重新检索全称、地域、候选信用代码、英文名、品牌。先建立主体锚点，再查产品、招聘、技术、资质、市场、联系方式、风险、数字化。英文名至少通过中英文同页原件或可解释关联与中文主体对应；同名、相似名、同域名不能自动合并。关联公司独立记录。

| 维度 | 优先入口 | 必须核对的细节 | 不可作出的推论 |
|---|---|---|---|
| 工商与股权 | 国家企业信用信息公示系统、年报；聚合页只供线索 | 全称、代码、登记时点、变更记录、法人/股东分别核对 | 存续不等于正常经营；法人不等于实控人 |
| 业务与客户 | 企业手册、主办方会刊、客户/监管公开附件 | 型号、制造商/品牌方/出口商角色、日期、范围 | 单型号不等于全产品；文书不等于实际订单或收入 |
| 招聘与组织 | 政府就业网、企业原发岗位，再看招聘转载 | 正文目标企业所在行、岗位日期、薪酬单位、邻近推荐栏 | 历史招聘不等于现有组织；旁栏岗位不属于正文企业 |
| 专利与软件 | CNIPA、登记原件；Google Patents作镜像 | 申请/公开号、类型、申请人、权利人、日期、法律事件、受让 | 外观不等于控制技术；申请不等于授权；专利不等于部署 |
| 资质与标准 | 发证方、政府原公告、有效证书 | 批次、拟/正式、编号、主体、型号、有效期、撤销 | 起草标准不等于认证；政府托管企业函不等于政府背书 |
| 市场与交易 | 主办方会刊、官方资金公告、交易原件 | 参展/中标/拟补助/到账不同阶段 | 参展不等于成交；名单金额不等于收入 |
| 风险 | 信用中国、执行公开、裁判与行政机关公开 | 精确主体、案号、事项、日期、完结与未决 | 未检索到或入口受限不等于零风险 |
| 数字化 | 官方披露，缺失则访谈 | 系统名称、实际使用、数据权限、负责人和样本 | 行业惯例、园区监控或旧项目合同不等于已部署AI |

检索过程：发现 → 打开原文 → 核对主体与定位 → 拆成原子断言 → 分配状态与证据ID → 找独立佐证或反证 → 记录缺口。搜索摘要、历史对话只作线索。不得绕过登录/付费/验证码。入口受限记录实际结果（如403、412、空正文），继续其他独立渠道，不能伪装查询完成。

PDF优先核对目标页和表头，记录从1计的文件页码与印刷页码；若工具无法给页码，至少记录唯一序号/展位/证号，并明确页码待核。OCR疑点需查看扫描图；图无法取得则披露文本层核验限制，不能声称肉眼核章。下载或归档不自动等于内容已核验。

## 4. 证据状态、引用与冲突

用户可见主状态只有三类，另带限定：

- **证实**：仅在已打开原文的明确范围内，例如“该会刊收录”“企业自述300余人”“镜像显示某公开日”。必须显式保留自述、镜像、历史限定；不把来源记载存在升级为现实全部属实。
- **推断**：由具体证据推导的流程/机会假设，列推导、替代解释及验证问题。纯方案建议也归此类。
- **未知**：未披露、未检索到、原文不可访问、主体冲突、口径冲突或待官方复核。未知不填0、不默认3分、不判定没有。

来源级别：A为职权范围内的政府/监管原记录；B为企业自述、展会原记录、交易方原文件；C为可追溯聚合/转载/专利镜像；D为摘要、聊天和无原文线索。网站托管单位与文件作者分开；级别不能自动决定断言状态。两个来源引用相同底稿仅计一个家族。

正文重要事实就近用“[E01](原文URL)”；方案推断引用依据，不给建议伪造事实来源。台账必须含ID、原子断言、主体、级别、状态、标题/发布者、URL、定位、发生日、发布日期、访问日/时区、源头家族、支持范围、冲突与下一步。未披露日期写未知。网页引用要可点击，禁止保留turn…、内部cite占位。必要原文短摘录可另记，不整页复制。

冲突处理顺序：主体 → 发生时点 → 口径 → 流程阶段 → 来源权威性。能解释保留不同范围；不能解释并列待核，不平均、不只选更新值。信用代码冲突会污染整份画像，必须隔离该页派生的人数、认证、风险评级等。当地登记与香港同名公司也不得合并。

## 5. 场景筛选器数据与行为

每项固定字段：id、name、department、value、ease、value_range、ease_range、status、confidence、evidence、input_output、gate、review、metric、alternative。7项是另一企业示范数量，后续企业数量由真实任务决定，不强凑场景。

V/E各1—5；默认排序P=V×E，次序为分数降序、ID升序；其他排序分别按V或E降序、ID升序。区间P下限=V下限×E下限，上限同理；区间是情景边界，不是概率区间。未知内部条件必须在门槛中写待确认；默认分属于显式假设，不能伪装内部准备度评分。纯公开研究置信度低。数据授权、审核、负责人、样本缺一均不能直接上线。产品控制必须独立工程验证，不能被高分抵消。

筛选部门以当前数据生成，默认全部；显示已选数量、空状态、重置按钮。重置恢复全部和P排序。卡片展示输入输出、出处、门槛、人工审核、验收指标、非AI替代和不确定性；不能只显示分数。打印输出全部场景静态表，不能只打印当前筛选子集。旧版五维100分制若启用，作为独立深化附件，不与P分数混算。

## 6. 访谈与试点字段

12个主题固定：业务目标；规模与岗位；产品与市场；客户需求流程；研发与版本；品质与售后；生产培训；采购仓储；现有系统；AI现状与授权；负责人预算；基线与验收。具体措辞随行业改变，每题须有对象、期望证据及决策影响。

勾选只表示讨论过；保存键至少含企业全称、模板版本与日期，禁止串企业。显示0—12进度；复制包含问题、对象、证据、影响及勾选；复制受限显示可选中文本框。清空重置本报告勾选，导出TXT作为浏览器持久化不可用时的备份。默认不存客户机密回答、不上传。

试点固定字段：名称/目标/任务范围、排除项、负责人、输入样本及授权、人工基线、评测集与训练集隔离、版本/权限、人工复核、验收建议、工期与成本项、停止/回退条件、推广条件。收益无内部数据则写待测，计算必须含复核、返工和维护；建议阈值明确“待客户确认”。

## 7. 地图和统一展示

母版地图组件为地址点位map_widget_v2，原参数仅地址/名称/图标/ID，未给坐标。跨运行环境不能直接复用私有组件。本版统一为地址卡、高德地址检索链接、按需加载的在线地图；地图加载后仍标明候选点位。地址未知时保留地图模块并显示待确认，禁止默认落到城市中心冒充厂址。未核坐标不得精确打点，未实测不得声称路线可达。

统一页面：深蓝页首、青绿强调、浅灰底白色章节卡；正文16px/1.85、最大内容宽1120px；11项锚点导航；表格横向可滚动；移动端390px正文无页面级溢出；状态同时用文字，不依赖颜色。字体使用本机中文无衬线；不需要外部字体或图片才能读正文。打印采用A4浏览器排版、每章分段、保留静态场景与全部问题，隐藏操作按钮。地图/来源需联网，阅读、筛选、勾选可以离线。

相同模板指共享structure.json及render_report.py生成的字段和布局，不代表不同公司必须有相同业务内容、行数或截图高度。原ChatGPT像素样式未获得，不能宣称像素一致。

## 8. 交付、运行与验收

Skill入口为enterprise-ai-presales-research/SKILL.md；结构真源为assets/structure.json；固定模板为assets/deliverable-template.md；数据字段参考assets/report-data.schema-notes.md。渲染器使用Python 3和markdown包：

```powershell
python scripts/validate_report.py 企业-报告数据.json
python scripts/render_report.py 企业-报告数据.json 企业-完整报告.html
```

必须分别报告：①结构一致性；②证据质量；③交互功能；④与历史原版的恢复边界。检查程序通过不证明企业事实真实。结构检查失败不得说“完全相同”；官方入口受限可完整交付带未知的公开研究，但不得说官方核验已完成。

验收至少覆盖：11章顺序、6个子节、3/4/9/10章表头、八工商字段、第九章12类、四阶段、12题、三交互定位、无悬空证据、分数及区间合法、过滤/排序/重置、勾选重载、企业隔离、复制降级、地图加载链接、打印全部场景、窄屏与中文阅读。保存对照表和实际结果；未测项明确未测。

本次第二家公司测试：另一企业11章与固定模板一致；原互动内容为重建；官方工商及专利状态、现场流程与实际数据准备度未知。后续新公司必须清空另一企业示例事实，逐条建立自己的证据。

## 内容保留迁移模式（2026-11-09）

用户明确要求已有报告仅改布局与交互时，用户指定版本是内容基准。保留原文件并记录SHA-256；将原内容映射到11章，不为套模板更改结论、评分体系、题数、工期或试点条款。新研究仍默认12题；迁移报告用content_preservation.baseline与interview_count声明基准及原题数，第七章标题与进度上限随题数变化。
