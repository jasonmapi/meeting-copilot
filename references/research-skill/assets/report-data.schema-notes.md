# 报告数据字段

报告JSON根对象：company（完整中文名）、short_name（章八替换用）、date（YYYY-MM-DD）、schema_version（2.0.0）、sections、sources、opportunities、interviews、addresses。

sections固定11项，顺序由structure.json决定；每项title及Markdown body。第5/6/7章分别包含<!-- widget:map -->、<!-- widget:opportunities -->、<!-- widget:interviews -->。子节与表头由规范固定。

sources每项：id、title（含发布者）、url、level、state、event_date、published_date、accessed（时区）、location、claim、limit（含冲突/补证）、family、subject。若一源支持多个相互独立断言，应分别列断言或分条，不能将量产、AI、专利合并成一句。ID必须唯一。所有字段非空，未知用明确文字。

opportunities每项：id、name、department、value、ease（1—5整数）、value_range、ease_range（两元素闭区间）、status、confidence、evidence（有效来源ID列表）、input_output、gate、review、metric、alternative。默认分必须在区间内。P渲染时计算，避免另存字段漂移。

interviews固定12项：id、theme、owner、question、evidence（希望取得的资料文字）、impact。ID唯一。这里evidence是资料需求文字，不是来源ID。

addresses每项：label（历史/候选/已核等状态）、address（公开地址）、evidence（有效来源ID列表）；地址未知可空数组，地图模块仍保留未知说明。

JSON及Markdown只使用可信本地编写内容。渲染器支持Markdown中HTML，不可直接输入未经审查的网页原文或用户上传HTML。来源URL须http(s)且检查主体；本版校验统一要求https。

依赖：Python 3，markdown。运行前确认依赖可用。渲染与验证命令见主规范。新企业从空字段填写，不复制另一企业值；模板是结构真源，示范数据仅用于理解字段。

## 内容保留迁移模式（2026-11-09）

用户明确要求已有报告仅改布局与交互时，用户指定版本是内容基准。保留原文件并记录SHA-256；将原内容映射到11章，不为套模板更改结论、评分体系、题数、工期或试点条款。新研究仍默认12题；迁移报告用content_preservation.baseline与interview_count声明基准及原题数，第七章标题与进度上限随题数变化。

评分为五维区间的旧报告设置scoring_mode=five_dimension_intervals；value/ease为空，value_range/ease_range对应原V/F，dimension_ranges保留V/D/F/R/O，score_range保留原总分区间，priority_group保留原访谈优先组。区间不能伪造成点分或V×E；双条的深色段为下限，浅色段到上限，默认按原访谈组展示，明确并列。其他维度及依据保留在原表详情中。原点分V×E报告继续原口径，两者仅共享展示组件。

访谈逐题保留优先级、问题、对象、证据、决策影响及followup_owner；页面详情、Markdown、复制、导出和打印均不得丢字段。四阶段统一外层标题，保留原阶段名称、条件、课程和试点全文；未给工期不得套用另一企业。

每家公司独立数据、证据台账和本机勾选键；样式和交互脚本应完全相同。验收包括原文件哈希、逐题字段、原机会区间、筛选排序重置、访谈刷新导出、四阶段详情、桌面/窄屏和打印。新查证结果另列核验增量；未获用户要求修改内容时不悄悄回写原结论。访问失败不等于事实不存在。结构一致不等于题数和企业事实相同。
